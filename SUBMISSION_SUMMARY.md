# BolMizan — Verified Submission Summary

**Verification date:** 15 November 2026  
**Project status:** Runnable prototype / early MVP; not production-ready for real merchants or funds until the release blockers below are addressed.

## Overview

BolMizan is a React 19 + TypeScript frontend served by an Express application. It contains merchant ledger APIs backed by SQLite in [server/realDatabase.ts](server/realDatabase.ts), a JSON-persisted sovereign-state store in [server/sovereignEngine.ts](server/sovereignEngine.ts), and user interfaces for scam-text analysis, transaction parsing, treasury operations, and ledger review.

The Shields view provides an English/Urdu/Sindhi/Arabic UI copy map in [src/utils/i18nSovereign.ts](src/utils/i18nSovereign.ts). A production-only service worker caches the app shell and same-origin static resources while bypassing APIs; this does not provide offline transactions or synchronization. Tenant ledger login issues signed, eight-hour `HttpOnly`, `SameSite=Strict` cookies; ledger reads and writes require the authenticated tenant to match the URL tenant. New ledger blocks use v2 SHA-256 hashes covering all stored financial fields, while legacy blocks retain their original verifier. The parchi form includes an optional pointer-based signature/thumb-mark canvas in [src/components/CustomerSignaturePad.tsx](src/components/CustomerSignaturePad.tsx) and can compute a local Web Crypto SHA-256 fingerprint. The Gemini parser and WhatsApp Cloud dispatch are optional integrations requiring credentials. The app also contains a local SBP Raast-style QR payload/CRC implementation in [server/realGateways.ts](server/realGateways.ts); this is not evidence of bank acceptance or settlement.

## Scope and limitations

These checks validate local code paths, not end-to-end banking, legal, Shariah, security, market demand, or performance certification. Mukasa tests calculate removal of circular ledger obligations; they do not move funds. Truth and scam filters use deterministic keyword/scoring logic and do not guarantee complete detection or a measured accuracy rate. The kill-switch blocks selected internal operations; it does not remotely freeze external payment providers.

**Remaining release blockers:** the session cookie is stateless; a stolen cookie remains usable until its eight-hour expiry, and logout clears the browser cookie but cannot revoke a copied token. New merchant enrollment is disabled in production because phone ownership/OTP verification is not configured. Shared sovereign writes are disabled in production except PIN-protected emergency/reset operations; role-based administrator authorization is still required. The PIN is a control secret, not an account identity system. AI rate limits are per-process rather than distributed. Have an independent security review and test reverse-proxy, TLS, and cookie behavior before public deployment.

A fresh store is empty unless `SEED_DEMO_DATA=true`, but an existing persisted [data/sovereign-ledger.json](data/sovereign-ledger.json) is loaded regardless of that flag and currently contains sample records. Back up and review that file before presenting dashboard balances as real activity.
